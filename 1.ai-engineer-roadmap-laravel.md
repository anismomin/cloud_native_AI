# AI Engineer Roadmap for a Senior Fullstack Developer

**Who this is for:** A fullstack dev (Laravel, React, Next.js, NestJS, DevOps) with 10+ years of experience who wants to become an AI Engineer — not an ML researcher. The goal is *building products with AI*, and every phase ships something you can use in client/agency work immediately.

**Total timeline:** ~6–9 months at 5–8 hrs/week. Phases overlap — don't wait to "finish" one before starting the next.

---

## Phase 0 — Mindset Shift (Week 1)

AI Engineering ≠ Machine Learning. You will mostly be calling models via APIs, not training them. Your fullstack skills (APIs, queues, caching, DevOps) are 70% of the job already.

**Read:**
- [The Rise of the AI Engineer](https://www.latent.space/p/ai-engineer) — swyx's essay that defined the role
- [What We Learned from a Year of Building with LLMs](https://applied-llms.org/) — the best practical field guide

**Toolbox gained:** Vocabulary + a mental map of the field so you stop feeling lost in AI Twitter/HN threads.

---

## Phase 1 — LLM APIs & Prompt Engineering (Weeks 1–3)

Learn to talk to models programmatically. This is your new "database layer."

**Learn:**
- Chat completions, system prompts, temperature, max tokens, stop sequences
- Structured outputs (JSON mode / tool schemas) — critical for real apps
- Streaming responses (SSE) — you already know this from web dev
- Prompt techniques: few-shot examples, chain-of-thought, XML/markdown structuring
- Multi-provider abstraction (OpenAI, Anthropic, Google, open models via OpenRouter)

**Resources:**
- [Anthropic Prompt Engineering docs](https://docs.claude.com/en/docs/build-with-claude/prompt-engineering/overview)
- [Anthropic's Prompt Engineering Interactive Tutorial](https://github.com/anthropics/prompt-eng-interactive-tutorial) (GitHub, hands-on)
- [OpenAI Cookbook](https://cookbook.openai.com/)
- [DeepLearning.AI — ChatGPT Prompt Engineering for Developers](https://www.deeplearning.ai/short-courses/) (free, ~1.5 hrs)
- PHP: [openai-php/client](https://github.com/openai-php/client) + [Prism](https://prismphp.com/) (Laravel-native LLM package)

**Build (pick one):**
- A Laravel Artisan command that summarizes support emails
- An API endpoint that extracts structured data (name, budget, intent) from contact-form submissions into JSON

**Toolbox gained:** You can add "AI features" (summarize, classify, extract, rewrite) to any existing Laravel/Next.js app this month.

---

## Phase 2 — Embeddings, Vector Search & RAG (Weeks 4–8)

RAG (Retrieval-Augmented Generation) = "chat with your data." This is the single most requested AI feature by clients.

**Learn:**
- What embeddings are (text → vectors) and cosine similarity
- Chunking strategies (size, overlap, semantic chunking)
- Vector stores: **pgvector** (start here — you already run Postgres), then Pinecone/Qdrant
- The RAG pipeline: ingest → chunk → embed → store → retrieve → augment prompt → generate
- Hybrid search (keyword + vector), reranking, citations
- Where RAG fails: bad chunking, retrieval misses, context stuffing

**Resources:**
- [DeepLearning.AI — Building Applications with Vector Databases](https://www.deeplearning.ai/short-courses/) (free short courses on RAG/embeddings)
- [pgvector](https://github.com/pgvector/pgvector) + [pgvector for Laravel](https://github.com/pgvector/pgvector-php)
- [Anthropic docs — Contextual Retrieval](https://www.anthropic.com/news/contextual-retrieval)
- LlamaIndex or LangChain docs (learn concepts; you don't have to adopt the framework)

**Build:**
- "Chat with our docs" for one of your own projects: ingest a docs folder or WordPress site, store in pgvector, answer questions with citations
- Bonus: semantic search for a client's blog/knowledge base

**Toolbox gained:** You can sell/ship document Q&A, semantic search, and support-bot features — the bread and butter of agency AI work.

---

## Phase 3 — Tool Use, Agents & MCP (Weeks 8–14)

Agents = LLMs that call functions in a loop. You already understand the hard parts (APIs, auth, retries, queues).

**Learn:**
- Function/tool calling: define JSON schemas, execute, feed results back
- The agent loop: plan → act → observe → repeat; when to stop
- **MCP (Model Context Protocol)** — the standard for connecting tools to models (you've already touched this)
- Multi-step workflows vs. autonomous agents — when each is appropriate
- Guardrails: timeouts, max iterations, human-in-the-loop approval, sandboxing
- Memory patterns: conversation history, summarization, external state

**Resources:**
- [Anthropic — Building Effective Agents](https://www.anthropic.com/research/building-effective-agents) (essential read)
- [MCP documentation](https://modelcontextprotocol.io/) + build a server with the TypeScript SDK
- [Anthropic tool use docs](https://docs.claude.com/en/docs/build-with-claude/tool-use)
- [OpenAI Agents guide / Swarm examples](https://cookbook.openai.com/)
- Vercel AI SDK (great for Next.js agents with streaming UI)

**Build:**
- An MCP server exposing one of your Laravel apps (e.g., "create invoice," "look up customer") — you already know the OAuth/transport side
- An agent that triages incoming leads: reads email → looks up CRM → drafts reply → asks human to approve

**Toolbox gained:** You can build internal automation agents and expose client systems to AI assistants — high-value, low-competition work right now.

---

## Phase 4 — Evals, Observability & Reliability (Weeks 12–18)

This is what separates AI engineers from demo builders. Non-deterministic systems need a different QA mindset.

**Learn:**
- Writing evals: golden datasets, LLM-as-judge, assertion-based tests
- Tracing/observability: log every prompt, response, latency, cost
- Prompt versioning and regression testing (treat prompts like code)
- Cost engineering: caching (prompt caching!), model routing (cheap model first), batching
- Failure handling: retries, fallback models, output validation (Zod/JSON schema)
- Security: prompt injection, jailbreaks, PII handling

**Resources:**
- [Hamel Husain — Your AI Product Needs Evals](https://hamel.dev/blog/posts/evals/)
- Tools: Langfuse (open-source, self-hostable — fits your DevOps skills), Braintrust, or promptfoo for CI eval runs
- [OWASP Top 10 for LLM Applications](https://owasp.org/www-project-top-10-for-large-language-model-applications/)
- [Anthropic docs — Prompt Caching](https://docs.claude.com/en/docs/build-with-claude/prompt-caching)

**Build:**
- Add Langfuse tracing + a promptfoo eval suite to your Phase 2 RAG app; run evals in CI (GitHub Actions — you know this)
- Cut your RAG app's cost 50% with caching + model routing, and prove it with dashboards

**Toolbox gained:** You can maintain AI features in production confidently — this is what makes you hireable as an *AI Engineer* rather than a tinkerer.

---

## Phase 5 — Open Models, Fine-tuning & Self-hosting (Weeks 18–26, optional but valuable)

Know when NOT to use a frontier API: cost, privacy, latency, or specialization.

**Learn:**
- Running open models locally: **Ollama**, llama.cpp, vLLM (production serving)
- Model selection: Llama, Qwen, Mistral families; quantization (what Q4/Q8 means)
- Fine-tuning basics: when it helps (style, format, classification) vs. when RAG/prompting is enough
- LoRA fine-tuning with Unsloth or OpenAI/Anthropic fine-tuning APIs
- GPU deployment: Modal, RunPod, or bare VPS with vLLM — your DevOps background shines here

**Resources:**
- [Ollama](https://ollama.com/) — run a model locally today
- [Hugging Face LLM Course](https://huggingface.co/learn) (free)
- [Unsloth fine-tuning notebooks](https://github.com/unslothai/unsloth)
- [fast.ai — Practical Deep Learning](https://course.fast.ai/) (only if you want deeper ML foundations)

**Build:**
- Self-host a small model behind an OpenAI-compatible API (vLLM) and route cheap tasks to it
- Fine-tune a small model to classify support tickets in a client's exact taxonomy; compare against prompting with evals from Phase 4

**Toolbox gained:** You can pitch privacy-sensitive clients (healthcare — you already serve them!) on-prem/EU-hosted AI, and slash inference costs.

**Do:**

- Write about what you build — the AI engineering field rewards public learning heavily
- Add "AI Engineering" services to your agency offering: AI feature integration, RAG systems, agent automation, AI audits

## Guiding Principles

1. **API-first, ML-later.** You don't need math to ship AI products. Add foundations (fast.ai) only if curiosity pulls you.
2. **Evals are your unit tests.** No AI feature is "done" without them.
3. **Your stack is an asset.** Laravel + Postgres + DevOps means you can ship pgvector RAG and self-hosted inference that pure "AI people" can't.
4. **Build in your domain.** Healthcare/wellness/B2B SaaS clients + AI = a niche most AI engineers don't have.
